## Adapted changes

1. **Always show Downloads** under UI, default off, restart required. Before the host updates proxy/download visibility, make its validated Downloads menu item visible and use the unforced update route. Telegram still handles search/selection/proxy layout. The local selector requires the mapped ActionBarMenuItem type, tag 3 and an ActionBar grandparent, rejects ambiguity and only caches a successful field. Installation state follows API 102 hook bookkeeping.
2. **Show user ID** now has **On my profile** and **On other profiles**. Each absent child inherits the previous switch independently; existing child choices are retained. No old preference is removed. Restart notices ensure already constructed views refresh.
3. **Profile centring**: modify status/ID text before the host measures and centres it; update the scrolling status copy for the user's own profile. Avoid a populated but hidden overlay when the primary status is visible. Correct exact width to the widest line while preserving drawable spacing. Only tracked module-owned ID labels are affected. Device review of the first candidate found that the host's single-line gradient/hardware layer can omit the added second line after scrolling despite correct accessibility text. The follow-up disables that gradient only for the module's two-line label and explicitly requests layout/redraw; fingerprint version 24 covers the typed gradient setter.
4. **Local safeguards**: rendering uses nested per-thread frames with unconditional cleanup, replacing upstream global current-view state. Weak view metadata values contain only ID/ownership; click handlers capture only the ID string. Stale numeric ID suffixes are removed before adding a different ID. Copy actions tolerate a missing Activity.
5. **Indonesian translations** adapted for 102 existing module labels, with the current module name retained. Missing module-specific strings keep English fallback. Both `id` and legacy `in` locale codes resolve. New controls are translated in all existing packs.

## Reviewed but deferred

- Restricted-content copy forwarding uses the globally selected account and synthesizes defaults for schedule/topic/paid-send arguments, so copying it could send to the wrong account context or lose user choices. Its temporary mutation of shared message/media objects also needs async ownership review. This feature is not transplanted; real server-side forwarding restrictions remain.
- Read-time display from v1.5 still needs bounded caching and correct account/refresh handling. Earlier deferral remains.
- Turrit prompts and Forkgram Classic drawer dispatch target routes not used by the current Play host. Donation/footer redesign, source deletion and dependency/workflow updates are not imported.
- Hidden legacy radio removal and automatic update schedules remain outside this change; no schedules are enabled.

## Hidden receipts and recurring unread counts

Suppressing channel/group read requests leaves the server read position behind. There is no independent persistent local read watermark, so a later server dialog refresh can restore old unread counts. The reported exact historical date was not verified against chat storage.

At the user's request, **Hide Seen > Channels and Groups** is now off while **Private Chats** remains on. This is a persisted device preference, not a new global default or an automatic mark-all-read operation. Existing unread backlogs need normal reading or an explicit mark-as-read action. Existing automated privacy cases cover passing channel/group reads while private reads remain protected; no private message was sent for this check.

## Limits

These checks cover the actual Play 13.1.1 host and selected UI paths; they do not prove every feature or every Telegram variant. Server-side deletion/expiring-media behavior was not re-exercised in this UI-focused change. Indonesian assets and locale resolution were checked, but the live host language was not changed. Delivery is a signed workflow artifact and pushed source; this change does not publish a separate stable release.

Private screenshots, UI trees, configuration backups and logs remain outside Git. No private messages, reactions, uploads, deletion, account logout or paid sends are used for verification.
