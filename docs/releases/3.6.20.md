## Changes

- Profile status/ID: suppress the native permanent clickable-label rectangle only while drawing tracked module labels, restoring click state afterwards.
- Poll footer: reserve annotation width before native author measurement and allocate a separate footer row once per native layout, preserving poll voting/timers.
- Settings: search, existing categories and concise descriptions; compact switches and existing preferences retained. Native TeleVip row now precedes Account (native row ID 1).
- Optional local reading position: account/dialog/topic-scoped persistent scroll/resume and monotonic visible-message watermark, only in conversations whose read receipts are hidden. Explicit message/date/topic navigation wins. No read request or host database write. The server/global unread counters remain server-owned; this option does not claim exact local unread-count reconstruction.
- Optional durable deleted-message copies: a separate local-state.db, not a migration of existing edit history. Future server-deleted cached messages are saved with text/caption and serialized metadata and browsed in an independent archive. It does not restore native chat/media files or reconstruct uncached content. Secret/expiring messages are excluded.
- Archive search, per-copy removal and user-selected JSON export/import. Plaintext backup warning; current-account-only merge, duplicate suppression, persistent deletion tombstones and conversation-clear cutoff. Logout cleanup rejects old queued writes and survives process termination. Limits: 10,000 rows/16 MiB decoded contents, 1 MiB per serialized row and 48 MiB backup input; full storage stops capture without evicting prior copies. Import streams rows in one atomic transaction.
- Optional additional local save/copy/viewer scopes for per-message and private sharing-protection metadata. Every temporary field is restored in reverse order, including failures/nested scopes. Existing saving switch must also be on. No synthesized forward/send request; secret/ephemeral handling stays separate.
- Local compatibility page: actual host/module versions, base APK digest, last verified target, hook/privacy health, local-storage issues and explicit end-to-end limits. No diagnostic upload.
- Optional new-chat mute default: use Telegram's original mute action after successful joins, current-user membership events and a first bot start. The bot path checks positive history before accepting a new conversation. Failed joins, pending approval/web challenges, other accounts, ordinary private chats and already-started bots are excluded. Apply once per account/dialog; subsequent manual unmute remains respected. No retroactive muting of existing conversations.

All new behavior switches default off. Existing keys/settings remain untouched. Restart after changing the new switches. New controls have English/Chinese text and existing language fallback.
