# TeleVip 3.6.19: Play Telegram 13.2.0

Date: 2026-11-05 (Asia/Taipei). Package `org.televip`, versionCode 361, version `3.6.19-telegram-13.2.0-api102`.

## Target and observed failures

The connected phone runs Play Telegram 13.2.0 (72801), Android 16. Installed host APK SHA256: `0887da322c8c68c18dd935ab7d9d8abd1b1f5c1ecf498c508904bb11596b1970`.

The initial 3.6.18 resolver/audit failed on changed settings and event classes, download account ownership, profile menu type and other active calls. Captured device logs repeatedly reported the missing promo preference getter and download account field. The full source inventory then exposed additional renamed/removed helpers and parameter reordering; fixing the entry alone was insufficient.

## Repairs

- Settings: retain the previous anchor and add release-surviving settings strings, distinguishing the main settings screen from Profile. Preserve the native row/callback alternatives and phone display scopes.
- Events: support the new internal notification dispatch parameter order. Resolve the TL error event by the last matching owner/type read before the distinctive `TL Error` branch, rather than hardcoding an event ordinal.
- Download safety: distinguish the ordinary DispatchQueue from the specialized Thread queue; support a void one-argument enqueue helper. Resolve the download's account from its real Premium policy call and the renamed UserConfig getter.
- Ads: obtain main preferences from the controller for the owning account, avoiding the removed static convenience getter and its repeated error logs.
- Parameters: runtime hooks now consume the actual parameter lists already published by the resolver. Type conversion supports descriptors, arrays and primitives without initializing host classes. Count formatting finds arguments by type; edit history distinguishes the grouped storage prototype instead of deciding from the client brand. Live edits without a protocol flag still retain their previous behavior.
- Media: identify the renamed image delegate by its enclosing chat and image/story handling. Resolve the renamed blurred-preview predicate. The optional inlined `isSecret` predicate is only hooked if present; the required TTL scope, preview predicate and canonical three-argument message path remain enforced. Convenience file path overloads delegate to that canonical method.
- Profiles: support the new single animated status and name fields while retaining the old arrays. Hook the native status update before measurement; preserve independent own/other IDs, status hiding, copy-name and copy-ID behavior. Resolve the forced text setter instead of assuming its obfuscated name.
- Deleted messages/read replies: support the reordered cache-marking helper and resolve its dialog cache; resolve the renamed update-array dispatcher. Channel read replies use the owning account's InputChannel helper. Difference updates accept the verified three/four-integer alternatives.
- Updates/icons: clear the typed pending-update field on initialization/config reload, retaining old updater hooks only where present. Read icon IDs from Android resources instead of depending on a stripped R class. Remove an unused storage getter.
- Fingerprint version 25 invalidates earlier mappings. No app data or existing user preferences are intentionally cleared.

## Limits

DEX matching and controlled Android tests do not prove server-side read visibility, remote deletion, paid sends or disappearing-media behavior end to end. Device verification uses existing/public content; no messages, reactions, uploads, deletion or logout are authorized for these checks. Private logs, preferences, UI trees and screenshots remain outside Git.

Official source was used as a structural reference ([Telegram Android](https://github.com/DrKLO/Telegram)); the installed APK is the authority for this exact Play build, since the public source tree may differ.
