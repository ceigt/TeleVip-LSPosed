## Reproduced failure and repair

The unchanged 3.6.14 audit rejects the actual 13.1.1 APK with `Invalid real-account download start scope`. Bytecode inspection shows that 13.1.0 queries `UserConfig.isPremium()` directly in the typed `start(stream, long, boolean)`, while 13.1.1 moves it into `updateDownloadByteBudget()`. Both `setIsPreloadVideoOperation` and its lambda call that helper outside `start`. Protecting only startup would miss those later budget decisions.

Select the nonstatic void/no-argument budget helper when present, otherwise the previous typed start method. A present but invalid/ambiguous helper is rejected without falling through. Preserve nested thread scope restoration and real-account speed gating. Refresh the fingerprint cache to version 20. The start fingerprint now anchors on `updateParams`, and the helper on the actual Premium query.

The DEX audit scans every method of FileLoadOperation and requires all direct mapped Premium queries to belong to exactly the selected policy method. A newly introduced unprotected query fails the gate. The sole optional symbol is the documented helper-versus-old-start route, enforced by this audit; no blanket exemptions are added. Missing policy and account negative controls still fail.

## Limits

These checks establish actual APK symbol/protocol compatibility, isolated regressions and the UI paths listed above. Download throughput and live byte-budget transitions were not measured with a disposable transfer. Server-side read visibility, newly received one-time media, real remote deletion/edit sequences and two-account privacy behavior remain unverified end to end. No private messages, bot commands, message deletion or account logout were used. The unchanged privacy semantics and the hidden radio decision from 3.6.14 are retained.
