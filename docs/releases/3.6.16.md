## Adapted improvements

### Edits received after a closed or offline chat

Previously only load type -2 captured edits. Normal history loads now inspect messages carrying the server edit flag (bit 15), preserving the cached previous text when it differs. The live-edit path remains supported even without that flag. Unedited normal loads do not query the host message table.

Account/dialog/message isolation, session revocation, capture-before-host-write queue ordering and cursor/byte-buffer disposal remain in place. There is no history migration or deletion. Edits before an original was cached and intermediate offline versions not returned by Telegram cannot be reconstructed.

### Telegram 13.1 story row

R8-inlined story checks can bypass the old hasStories method hook. The new constructor hook wraps only the two mapped presentation lists, filters PeerStories while hiding is enabled, and handles already cached entries. Upload lists, maps and storage are not replaced.

The exact int-account constructor, the first two ArrayList writes and their nonstatic field types are audited against the actual DEX. Final instance fields are exercised in Android tests. Existing switch defaults and restart requirements remain unchanged. Fingerprint cache version increases to 21.

The upstream read-time feature is deferred: its unbounded caching and account refresh handling need a separate design. Donation/footer changes, rewritten repository history and unrelated settings redesign are not copied. The previously deferred hidden-radio removal remains outside this change.

## Limits

Isolated host decoding/queues are controlled boundaries. Real remote edits require user-prepared disposable content; no private messages, bot commands, remote deletion or account logout are used. Two-account receipts, fresh one-time media, download throughput and real edit sequences are not certified by these checks. Automatic update-check schedules remain disabled.
