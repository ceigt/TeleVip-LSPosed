## Review items addressed

1. Archive explicit-deletion cleanup accepts only regular message mode, leaving scheduled/quick-reply/welcome namespaces alone.
2. Four no-flags legacy wire constructors are deserialized, copied into current native message/service/empty serializers and serialized into a separately owned buffer before marking. The trusted SQL message ID repairs a previously sign-bit-corrupted ID when that row is processed. No blanket rewrite of historical host rows is performed.
3. An expired read-time callback leaves timeout ownership intact; actual coordinator tests cover timeout label completion and cancellation.
4. A forum's automatic start-message argument can use the local position; an explicit highlighted jump retains precedence.
5. Document operation identity/account/type is persisted privately. An early framework callback retains results until asynchronous mappings/config initialization completes. Results attach to the returned Activity instead of requiring the original instance; monotonically rotating request codes reject stale results.
6. Bot starts respect explicit notification overrides and query positive native dialog history as well as cached messages, preserving existing conversations after message-cache loss.
7. Seconds apply only to formatter patterns containing unquoted hour/minute fields and no date fields.
8. Pending captures reserve a shared byte budget before copying; every completion/error/early return releases the reservation. Capacity failures retain existing copies and are reported rather than allowing unbounded queued memory.
9. Transactional insert/delete triggers maintain archive count/bytes; each import row no longer scans all previous rows.
10. A single bounded document task spools into an app-private temporary file. External providers use their own thread, never the module storage queue; temporary files are removed in finally.
11. Archive previews contain no binary payload. Debounced queries run off the UI thread and return at most 51 rows for a 50-row page; Unicode case folding is retained.
12. Session mint/revocation share a lock; queued deletion events capture their session before dispatch. Import retains the initiating token. Stale work cannot adopt a later login epoch.
13. Cleanup is attempted even when persisting revocation fails. Native logout completes before cleanup can unblock a fresh login; native failures retain revocation while still attempting data deletion.
14. ttl_period ordinary auto-delete messages are excluded alongside secret/message/media TTLs. The same exclusion is used for read-time/save scopes.
15. Native date-range delete intent creates an account/dialog/date tombstone and deletes matching archive copies, including copies no longer in the native cache. Old backups cannot restore that range.
16. Account-owned windows dismiss on external navigation/logout and validate the account/session while visible and before actions. Read-time dialogs share the same protection.
17. Dialog-clear cutoffs use the owning Telegram account's server clock.
18. A reader bounds raw JSON strings/literals before JsonReader allocates complete values; row/file/decoded-size validation and transaction rollback remain.
19. Regression compilation includes production ArchiveUi and ReadTimeMenu. Added controlled request/window/timeout tests and deterministic logout, failed-marker and legacy-conversion cases; these do not contact Telegram servers.
20. Cloud build/sign requires a source-bound successful real-Play audit record. Missing/stale evidence fails the gate. The workflow explicitly verifies recorded local evidence; it does not claim to download or rerun an APK in the cloud. Telegram APKs are not redistributed, and website-client results do not substitute for Play evidence.
