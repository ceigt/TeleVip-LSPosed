# TeleVip 3.6.10 verification

Target: installed Telegram Play 13.0.1, versionCode 71671; Android 16 with LSPosed API 102.

## Changes

- Startup and settings readiness are tracked separately from dispatcher installation. Failed initialization retries three times, rather than declaring a failed settings route ready.
- Startup requests are released after the initialization attempt, after a 20-second watchdog or when the bounded queue is full. The bootstrap interceptor remains installed and applies the same selective privacy policy whenever the main privacy hook is unavailable. Ordinary traffic is not retained indefinitely.
- Request classification uses exact protocol class identities and cached resolved classes. Known protected receipts are suppressed before constructing responses. Peer/status/response failures remain suppressed and produce a visible warning, instead of silently passing the request to the network.
- Normal and timestamp callbacks receive the appropriate local response, including Bool for typing/encrypted read and an empty Vector for story reads. Response construction faults attempt a local 503 completion. Callback failure is reported without resending the suppressed request.
- Warnings appear on a foreground Telegram activity and remain visible in TeleVip settings while the issue persists. Unknown/changed protocol types cannot be promised protection; missing required identities are explicitly reported.
- Secret-media opening owns a temporary TTL override, with restoration for normal, nested and exceptional exits. Secret/blur-preview overrides are scoped to the message currently being opened.
- The forced gallery button is enabled only for secret-media saving or removal of content-saving restrictions.
- Message menu construction does not query the history database. Selecting the history action reads in the background and reports an empty history. Account session validation uses concurrent state rather than waiting for the write-transaction lock.

## Limits

The isolated tests verify exception handling, callback dispatch and restoration with controlled host objects. No new messages were sent, no accounts were logged out and no remote messages were deleted. Two-account receipt behavior, newly received one-time media and long-term history performance were not retested end to end. This release addresses review items 1, 2, 4, 5, 6 and 9; other review items remain deferred.
