## Findings and repair

The unchanged 3.6.12 audit fails fingerprint/name agreement: the protocol-id fingerprint for TL_channel selects TL_channel_layer232. Telegram 13.1 retains the previous protocol id in that older concrete subclass. The name-based route in this Play APK still finds the current TL_channel; this finding is not evidence that all channel functionality was broken on the device.

Adapt the upstream layer-aware constant source for this symbol only. When the class writing the old id has a concrete parent, that parent is the current type; an abstract parent leaves the original candidate unchanged. Keep constructor and primitive-argument registry exclusions. Fingerprint version 18 invalidates cached mappings.
