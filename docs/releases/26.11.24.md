# TeleVip 26.11.24 candidate

## API identity consistency

The follow-up review found that Passkey login reads BuildVars.APP_ID and APP_HASH directly. This revision applies a configured identity to that shared pair and to both SMS and Passkey request serializers, alongside the existing early native network initializer. It covers requests constructed before the normal feature hooks finish loading.

The shared field-update helper rejects invalid inputs, wrong field types, mixed static/instance pairs and final fields before writing. JVM checks cover static and request-instance application, unchanged values on invalid input and rejection of a read-only target. The authenticated Play 13.3.1 (73461) audit now requires 19 extra method shapes and 23 typed fields, including the Passkey request serializer and its API ID/hash. Each required mapped member has an individual removal control.

## Validation scope

The target remains the device-extracted Google Play APK documented in [26.11.23](26.11.23.md), SHA256 d8e1bcbb8899c80a6308d9dbb449cecccae26076a40b357902054fc605ed11ea. The complete real-APK audit passes 543 required call sites. The maintenance JVM policy suite passes 54 assertions.

The unchanged optional contact, profile, forwarding and translation implementations have the device checks recorded in 26.11.23. The Android isolation baseline is 23 groups / 3145 assertions. This revision leaves all six optional switches off by default. The test preferences and temporary system settings from the earlier device checks were restored before this build.

Original-certificate cloud build, final APK provenance and in-place installation results will be recorded after completion. A real authentication attempt with the user's own API credentials, SMS fee payment and server-side privacy/delete/edit scenarios still require separate end-to-end validation.
