## Findings and changes

- Telegram 13 renamed secret read and view-once delete schedulers to `ib` and `P4`. The former hardcoded `db`/`N4` hooks failed. Resolve behavioral fingerprints, then validate Runnable return, exact arguments and permitted static receiver layout.
- The secret viewer close callback is now `o1`. Resolve its behavior as the last Runnable read by closePhoto; leave animation completion intact.
- Adapt upstream class-fact alternatives, wildcard return support, pending alternative field resolution and additional resource-ID/fork signatures. Increment fingerprint cache generation to 16.
- Add sponsored response and cache filtering to the existing request-completion and account-specific proxy promo cleanup.
- Cover all three exact FileLoader message path overloads. Bind overrides to the actual weakly referenced message instance to avoid ID collisions across accounts/conversations; missing local files retain host behavior.
- Correct the non-Play secret viewer's argument guard and null place-provider handling. That branch was reviewed but was not run on a fork client in this session.
- Use a concurrent map for ad request types so callbacks remain safe during partial installation retries.

## Limits

The UI navigation and isolated instrumentation cases do not prove every feature's server behavior. No other fork was installed or certified. Full APK decompilation reported errors; required interface conclusions were independently checked against the actual DEX.

The connected phone's USB stay-awake setting is restored after verification. No messages were sent, accounts logged out, templates changed or Telegram data cleared during testing.
