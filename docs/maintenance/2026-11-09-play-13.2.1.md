## Audit scope correction, with evidence

The unchanged audit initially reported one required missing name, `Browser#openUrl` in `virtuals/messenger/browser/Browser.java`. All critical hook, selector, protocol and cache checks passed. APK inspection shows the current browser dispatcher gained an extra boolean argument; the old Progress-type dependency no longer resolves, leaving that legacy helper's mapping unavailable.

This is not a used Play feature failure. A repository-wide caller check finds this wrapper only in `SettingsController` and `SettingsAdapter`. `TeleVip.startHook()` returns through `NativeSettingsEntry.init()` for the Telegram client before constructing the legacy controller. The actual Play dialog is `SettingsFallback`, whose link action uses Android ACTION_VIEW directly. The native row and dialog were opened on the phone.

The test tool now classifies only that exact wrapper call as inactive for `org.telegram.messenger`. Every Play run verifies the two callers and the early return before controller construction. Negative cases reject a new caller, removal of that early return, another source, another method and the website package. No other unresolved site is waived; no runtime resolver, fingerprint, cache version, browser behavior or feature code changes. This correction does not certify the legacy helper on other clients.
